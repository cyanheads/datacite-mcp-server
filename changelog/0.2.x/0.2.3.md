# 0.2.3 — 2026-11-25

## Added

- **`bbox`** (`west`, `south`, `east`, `north`) on `datacite_search_works` matches works with a point, box, or polygon vertex in the box; each row carries `inBbox`, false when only coordinates from different locations matched. Keys other than the four fail as `invalid_arguments`; a notice counts cross-paired rows, in the singular for one. ([#48](https://github.com/cyanheads/datacite-mcp-server/issues/48))
- **`sections`** on `datacite_get_work` returns only the named record groups beside the identity fields; `content[]` marks the work's rights as "left out by sections" when they are omitted. ([#50](https://github.com/cyanheads/datacite-mcp-server/issues/50))
- **`rightsUris`** on `datacite_search_works` rows lists each deposited `rightsUri`. ([#46](https://github.com/cyanheads/datacite-mcp-server/issues/46))
- **Related item fields** on `datacite_get_work`: `volume`, `issue`, `number`, `numberType`, `firstPage`, `lastPage`, `edition`, `publisher`, `publicationYear`, `creators`, and `contributors`, each absent when not deposited. ([#47](https://github.com/cyanheads/datacite-mcp-server/issues/47))
- **Server `instructions`** state that a backslash before punctuation in `content[]` is Markdown encoding; a zero-hit `query` containing `\*` gets a notice that it matches a literal asterisk.

## Changed

- **A request past DataCite's 8,201-byte URL limit** fails before it is sent as `request_too_long` (`-32007`, with byte counts and each input's share of the URL) on `datacite_search_works`, `datacite_search_repositories`, and the `datacite_trace_relations` root lookup; 0.2.2 sent it and relayed `-32600` "DataCite returned HTTP 414." ([#45](https://github.com/cyanheads/datacite-mcp-server/issues/45))
- **`datacite_trace_relations` at depth 2** expands only the neighbours whose reverse lookup fits DataCite's URL limit and says how many; 0.2.2 lost the whole call to HTTP 414. Its notice names a `datacite_search_works` query only when every page of that search fits.

## Fixed

- **"none declared" label and zero-hit notice**: a search row whose license has no `rightsIdentifier` reads "no license id" and links its URIs, and the `licenses` zero-hit notice states the `rightsIdentifier`-only scope and a `rightsList.rightsUri` query for URI-only licenses; the "is not a DataCite field" notice no longer flags `_exists_:` or the server's own `relatedItems.*` paths. ([#46](https://github.com/cyanheads/datacite-mcp-server/issues/46))
- **HTML entities and tags** in names, publishers, subjects, and funders are decoded as titles are, on both surfaces. ([#49](https://github.com/cyanheads/datacite-mcp-server/issues/49))
