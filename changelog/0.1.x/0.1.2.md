# 0.1.2 — 2026-10-09

Framework update and maintenance. No tool is added, and no tool's input or output schema changes.

## Added

- **Public hosted instance** — `https://datacite.caseyjhand.com/mcp`, listed under `remotes` in `server.json` and in a new README section. Every caller of the hosted instance shares one DataCite request budget.
- **`.env.example`** — documents `MCP_REQUEST_STATE_KEY` and `LOG_LLM_INTERACTIONS` (comments only; this server sets neither).

## Changed

- **Tool error results carry `data.requestId`** — the id the server's log records for that call carry (framework 0.13.10).
- **Boolean and optional arguments are repaired before validation** — `"true"`/`"false"` for `include_facets` and `include_child_funders` on `datacite_search_works`, and `null` at an optional argument (treated as absent), were rejected before and are accepted now (framework 0.13.14). Numeric strings and lone strings for list arguments are still rejected here: every integer and list argument sits behind a `z.preprocess` helper that the repair does not reach (cyanheads/mcp-ts-core#725).
- **Argument rejections are bounded in size** whatever the caller sends (framework 0.13.14).
- **MCP SDK 2.1 transport rules** (`@modelcontextprotocol/server` 2.0.0 → 2.3.1 in the lockfile) — a JSON-RPC batch over 100 messages is refused, and on stdio, stdin EOF aborts requests still in flight (framework 0.13.9).
- **`server.json`** — both npm entries drop the `run start:stdio` / `run start:http` package arguments, which a registry client hands to the package's bin and which it does not take, and use `runtimeHint: "npx"` in place of `"node"`. The `streamable-http` entry now sets `MCP_TRANSPORT_TYPE` to `http`; before, it never selected the HTTP transport.
- **Docker** — the `deps` stage runs `scripts/prune-musl-packages.ts`, removing musl-only package variants the glibc runtime image never loads; OpenTelemetry peers install through `scripts/install-otel.ts`.
- **Declared recovery hints** — handlers and the upstream client no longer forward `ctx.recoveryFor(...)`; the framework fills a declared reason's hint itself. Internal; callers receive the same hints.
- **Repo hygiene** — `.gitignore` and `.dockerignore` ignore every `.env*` file except the templates, `.mcpbignore` excludes `.cache/`, the CodeQL workflow analyzes each language under its own category, and `framework-skills/`, `CLAUDE.md`, and `AGENTS.md` follow the 0.13.14 framework docs.
